# OpenVireo Developer

The source of [developer.openvireo.com](https://developer.openvireo.com): docs for building on OpenVireo with the
TypeScript SDK, the `ov` CLI, the sync server HTTP API and the Rust core bindings. Built with
[Astro](https://astro.build) and [Starlight](https://starlight.astro.build).

## Where the docs come from

Most pages are **generated**: the Markdown lives next to the code in each repo, and `npm run sync` publishes it
here. Edit the docs there, not here.

| Section | Source |
|---|---|
| `/sdk/`, `/cli/` | [`openvireo-sdk/docs`](https://github.com/openvireo/openvireo-sdk/tree/develop/docs) |
| `/sdk/api/` | TypeDoc, built from `openvireo-sdk` |
| `/api/`, `/self-hosting/` | [`openvireo-sync-server/docs`](https://github.com/openvireo/openvireo-sync-server/tree/develop/docs) and its `openapi.yaml` |
| `/bindings/` | [`openvireo-core/docs/bindings`](https://github.com/openvireo/openvireo-core/tree/develop/docs/bindings) |

Written here: the home page (`src/pages/index.astro`), `/guides/` (`src/content/docs/guides/`, cards from
`src/data/guides.ts`) and the theme (`src/styles/theme.css`, `src/components/`).

### Code in several languages

Consecutive fenced blocks marked `tab="Label"` in a source repo's docs become one tabbed group here (GitHub
shows them as ordinary blocks one after another). The reader's language choice applies to every group and is
remembered (`src/plugins/remark-code-tabs.mjs`, `src/scripts/code-tabs.ts`):

````md
```ts tab="TypeScript"
...
```
```python tab="Python"
...
```
````

Every page is also served as Markdown at `<path>.md` (the "Copy as Markdown" button), and `/llms.txt` indexes them.

## Sync the docs

The source repos are expected next to this one (`../openvireo-sdk`, `../openvireo-sync-server`,
`../openvireo-core`); `OPENVIREO_SDK_SRC`, `OPENVIREO_SYNC_SRC` and `OPENVIREO_CORE_SRC` override that.

```sh
npm run sync                                   # each repo at its latest release, plus later docs-only commits
npm run sync -- --sdk-ref develop              # one repo at a branch, tag or commit, as it is there
npm run sync -- --ref origin/develop           # everything at develop (a preview of unreleased docs)
npm run sync -- --only sdk --no-typedoc        # one repo, skip the TypeDoc build
```

### Versions

The site describes what's released, not what's on develop. By default each repo publishes its newest
`vX.Y.Z` tag. Docs fixes made after that release still go out: each later commit on `origin/develop`
(`--branch` to change) that changes only docs (`*.md`, `docs/**`) is merged into the released files,
three ways, file by file. A file that unreleased code also changed, or whose fix doesn't merge, stays as
it was released, and the run lists it as "held"; it catches up at the next release (or sync that repo
with `--<repo>-ref develop` if the held text is wrong today).

- Fenced code blocks have `X.Y.Z` / `vX.Y.Z` replaced with the release, so install commands paste as they are.
- `data/releases.json` holds the releases. The header pill and the home page show them.
- Each repo's `CHANGELOG.md` becomes `/changelog/<repo>/`, without its `## Unreleased` section.
  `/changelog/` (written here) explains the versioning. Add to `## Unreleased` as you go; at a release,
  rename it to the version and date.
- In the source docs, `(added in 1.1)`, `(added in core 1.2)`, `(changed in ...)` or `(deprecated in ...)`
  in a heading or a paragraph becomes a badge (`src/plugins/remark-since.mjs`). Heading anchors don't change.
- When 2.0 ships, snapshot the 1.x docs under `/v1/`.

It replaces `src/content/docs/{sdk,cli,api,self-hosting,bindings}` and `changelog/{core,sdk,sync-server}.md`,
`public/api/openapi.yaml` and `public/sdk/api/`, and writes `data/redirects.json` (the old
`openvireo.com/docs/...` URLs and where they live now) and `data/releases.json`. Commit the result.

## API references

Each language's reference is generated by its own tool and committed under `public/reference/<lang>/`
(TypeScript's is `public/sdk/api/`, built by `npm run sync`). `/reference/` links them all.

| Language | Tool | Script |
|---|---|---|
| Rust (`openvireo-core` and the crates in its API) | rustdoc | `npm run apidocs:rust` |
| Kotlin / Java | Dokka / javadoc over kapt stubs | `npm run apidocs:jvm` |
| Swift (`OpenVireoRustCore`) | DocC, static hosting | `npm run apidocs:swift` (macOS + Xcode) |
| Python (`openvireo`) | pdoc | `npm run apidocs:python` |
| C++ (`ovcore.h`, `host.h`, the cxx bridge) | Doxygen | `npm run apidocs:cpp` |

`npm run apidocs -- --ref <core ref>` runs them all from one openvireo-core ref (default `origin/develop`;
`--skip swift` off macOS). Each script archives the ref into a temp dir, so the core checkout is never touched.
Needs Rust, JDK 17+, uv or Python 3.10+ and Doxygen; the first JVM run downloads Dokka.

## Deploy

`develop` deploys to DigitalOcean App Platform on push (`.do/app.yaml`, the `Dockerfile` builds the site and
serves it with nginx). `./deploy-do.sh` creates or updates the app and its DNS record.
