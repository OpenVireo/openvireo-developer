Detailed Description

The Host interfaces the desktop implements in Qt (rust-core-tasks.md §2.2, crates/ov-core/src/host.rs).

Each class is a pure-virtual C++ mirror of one Rust Host trait. Implement them, hand them to ov::new_client() as std::unique_ptr, and the core calls them back through cxx.

Rules for implementations:

  • Thread safety: the core may call any method from any thread that is inside a core call, and concurrently. Guard shared state. (Qt: don't touch QObjects owned by another thread without a queued/blocking connection.)
  • Blocking: methods are synchronous. A call returns when the work is done (e.g. the HTTP response has fully arrived). The core calls them from the worker thread that made the core call, never from the thread that owns the UI unless the app calls the core from there.
  • Errors: HttpTransport/ByteStream report transport failures through failure (kind + text) and return a default-constructed value. Everything else reports errors by throwing; the exception's what() may start with an ov wire code and ": " (e.g. "forbidden: keychain locked") to choose the OvError code, otherwise the code is "internal".
  • Secrets: values passed to SecureStore::set are secrets; wipe your copies.

This header is included by the generated bridge before the shared structs are defined, so it only forward-declares them. Include "ovcore.h" in your own code, not this file.
