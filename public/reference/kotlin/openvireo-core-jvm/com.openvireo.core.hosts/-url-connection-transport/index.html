UrlConnectionTransport

class UrlConnectionTransport @JvmOverloads constructor(connectTimeoutMs: Int, readTimeoutMs: Int, dispatcher: CoroutineDispatcher = Dispatchers.IO) : HttpTransport(source)

An HttpTransport over HttpURLConnection, run on dispatcher (Dispatchers.IO). It works on the JVM and on Android (where HttpURLConnection is OkHttp underneath); on the JVM prefer JavaNetHttpTransport.

As ov_core::host::HttpTransport requires:

  • No redirects: instanceFollowRedirects = false, so a 3xx comes back as a response and the core refuses it.

  • Any status is a response: 4xx/5xx bodies are read from errorStream, not thrown.

  • Headers: the request's headers, in order, plus what the platform always adds (User-Agent, Host, Content-Length, Accept-Encoding on Android). Header values may be bearer tokens and are never logged.

  • Errors: no network, DNS failure or connection refused → TransportException.Offline, a timeout → Timeout, TLS → Tls, anything else → Other; cancelling the calling coroutine disconnects the request.

  • Cookies: none are added unless the app installed a process-wide CookieHandler (CookieHandler.setDefault), which HttpURLConnection always consults. Don't install one in a process that uses this transport, or use JavaNetHttpTransport.

  • PATCH: the JVM's own HttpURLConnection can't send it (Android's can); such a request fails with TransportException.Other. The core uses PATCH for org, vault and service-account renames.

connectTimeoutMs bounds connecting; readTimeoutMs bounds each read of send (streams wait without a read timeout, since server-sent events can be quiet for a long time).
