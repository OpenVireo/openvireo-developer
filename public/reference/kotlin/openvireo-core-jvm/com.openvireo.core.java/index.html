openvireo-core-jvm/com.openvireo.core.java

Package-level declarations

The API for Java, without coroutines: J<Object> wrappers (JOvClient, JAccount, JVault, ...) whose suspend methods return CompletableFuture, JOv (every free function as a static), JRecords (records with unsigned fields), JErrors, and the future-based Host interfaces with JHosts and JDefaultHosts. Generated from the binding on every build, so it can't drift from it.

JHosts
Link copied to clipboard
object JHosts

Builds a Host from Java, and adapts between the Java Host interfaces and the generated (suspend) ones. Each part of a Host is either a Java one (JHttpTransport, JSecureStore, JBlobCache) or a shipped or Kotlin one (JavaNetHttpTransport, MemoryStore, FileCache, ...). JDefaultHosts.builder() starts with the platform's defaults filled in.

JHttpTransport
Link copied to clipboard
interface JHttpTransport

HTTP, as ov_core::host::HttpTransport needs it. Never follow redirects (a 3xx is a response) and never add cookies. Any status is a response: complete with it, not exceptionally. Complete exceptionally with a TransportException (Offline, Timeout, Tls, Cancelled, Other); any other exception is mapped (ConnectException/UnknownHostException → Offline, a SocketTimeoutException → Timeout, an SSLException → Tls, else Other). The core may cancel the returned future when the call it belongs to is cancelled.

JRecords
Link copied to clipboard
object JRecords

Kotlin hides constructors and getters with unsigned types from Java. For each record and enum variant with an unsigned field, this has a new<Record>(…) factory (unsigned → the next wider signed type, range-checked) and a get<Field>(record) getter for each unsigned field. Every other field reads as usual (record.getName()).

object JScope

The coroutine scopes the Java facade's futures run on. Every J wrapper takes one (its constructors also take an Executor); the default is defaultScope.

JSecureStore

interface JSecureStore

Secrets that persist (the OS keychain, for example); keys are chosen by the core. Complete exceptionally with an OvException (JErrors.ovException) when the store can't be read: that is not the same as a missing key (null).
